# ジオラマ魔物記 — 作り方の方針(オーナーから)

- 仕様は `docs/SPEC_DEMO.md`。ここに書いた方針が仕様書と食いちがったら、このファイルを優先する
- 遠慮しないで、いちばんいいものを作る。大まかな指示と全体の方針さえ守れば、細かいことはすべて任されている
- 迷ったら、より大きく・より多く・よりおもしろい方を選ぶ。確認の質問で止めずに、決めて作って、何を決めたかを短く伝える(`docs/DECISIONS.md`)
- ギミックは **1エリアにつき1つの新しいルール**。見た目だけ変えた同じ仕掛けは禁止。古いルールは、新しい能力と組み合わせたときだけ再登場させる
- 行けない場所・詰む状態がないことは、ソルバー(`tools/solver/`)とテストで必ず確かめる
- すべての建物に入れる。入ると屋根と手前の壁が持ち上がって中が見える(画面の切り替えなし)

# 見た目の方針

- 3D(Three.js r160 を `vendor/` に同梱して固定)。斜め上からの狭い画角 + ティルトシフトで「机の上のジオラマ」に見せる。エリアの外には作業台と巨大な道具が見える
- 魔物は「ソフビ人形調」。Blender(bpy)のスクリプトで作るパーツ(胴・頭・背中・しっぽ)をソケットでつなぐ。目は全種共通のガラス玉の規格。生成AIの画像や画風のちがう素材は混ぜない
- UI は「プラモデルの組立説明書調」: 生成りの紙の地、黒いインクの線、太いゴシック、数字は Barlow Condensed、メニューはランナーの形。UIに影や光のにじみは使わない。エリアのアクセント色を1色使う
- 既存IP(ポケモン、ドラクエ、デジモンなど)に似せない

# 道具と規格

- 性能の上限: 画面の三角形 15万、描画呼び出し 150回、初回の読みこみ 15MB。`renderer.info` で測る
- セーブは版番号つき。版を上げるときは移行の関数とテストを書く
- main に push しない。デプロイしない
