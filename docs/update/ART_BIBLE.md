# 魔生物アートバイブル(確定版 v1.0 / 2026-11-18 / アート総監督)

- 対象: 魔生物 159 種(`DRAW` 145・`DRAW96` 10・`shinDraw` 4)の手続き描画
- 前提: 外部画像・画像生成 AI は使わない。`flatPainter` と `sprite()`(`src/game.html` 931・962 行付近)の手続き描画で「立体フィギュア調」に統一する(CLAUDE.md)
- 試作: `docs/update/art_proto/proto.html`(game.html の描画部品を写して画風の値だけ変えたもの。game.html は変更していない)
- 比較画像: `docs/update/art_proto/00_current_all.png` 〜 `06_check_stats.png`
- 採用案: **B「トイ・フィギュア」**(最終決定は指揮官。理由は 2 章)

## 1. 現状の弱点(実測と目視)

全 159 種を描き出して並べた画像(`00_current_all.png`)と、`proto.html` の `check()` と同じ方法で測った値から。

| # | 弱点 | 根拠 |
|---|---|---|
| 1 | **目がない・目が点** | `g.eye()` を呼ぶのは 159 種中 56 種。103 種は目がないか、`g.r(x,y,1,1)` の 1 単位の点(192px で 4px、48px で 1px)。虫系は 17 種中 16 種が `eye()` なし。48px では目が消える |
| 2 | **暗い体が背景に沈む** | 黒い地の UI に黒い外ふち `#070916`。体の平均輝度が 70 未満の 6 種(kurobikari, jorou, hikui, yatagarasu, ookuwa, manjushage)と、ハシブトンなどの濃紺の体は 48px で輪郭が読めない |
| 3 | **外ふちが細い** | 192px で 3px。48px 表示では 0.75px になり、ふちとして効かない |
| 4 | **横向きの写実寄りの体で、枠の中で小さい** | 横に長い体(oohanzaki, kanahebin, akahara は縦横比 2.2 超)。占有率は平均 33%、ハシブトン 27%・カブトオー 24%。上の余白が 50px を超える種がある。アンカー(足もとの位置)の規格がない |
| 5 | **シルエットが似る** | 四足獣は「楕円の胴+円の頭+棒の脚(`LEGS` 25 件)」の同じ組み立て。48px シルエットで見ると、獣系のネズミ・イタチ・カモシカなどの区別がつきにくい。種の「看板」(角・葉・くちばし)が小さい |
| 6 | **色違いが hue-rotate だけ** | `.seal img.spr.shiny{filter:hue-rotate(150deg) saturate(1.5)}`。タヌキが水色、カラスが茶色の小鳥、カブトムシが緑になるだけで、光の演出もない。種ごとに意図した配色にならず、肌や目の色まで回ってしまう(`03_compare_shiny.png` の左列) |
| 7 | **進化・上位でシルエットが育たない** | `shinDraw` は基本形に放射状の光と星を重ねるだけ。形は同じ |
| 8 | **系統と色の対応がない** | 描画内の色は 785 種の手入力。`FAM.c` / `IRIS` とのつながりがない。`myst`(？？？？系)は `IRIS` に項目がなく(`IRIS` にあるのは系統にない `god`)、目の色が既定値 `#ffd23a` になっている |
| 9 | **描き込みの量の差** | 定義の長さは 239〜1,911 文字。短いもの(kanahebin, aodaija, numekuji)は情報が少なく、48px で棒や楕円にしか見えない |

## 2. 方向性 3 案の比較と推奨

同じ 3 体(系統と体の形がちがうもの)を、形の設計は共通にして、画風の値だけ変えて描き比べた。

- ハッパダヌキ(獣・四足・頭に葉) / ハシブトン(鳥・暗い体) / カブトオー(虫・細い角と脚)
- 形は 3 案共通で描き直した(頭を大きく、看板を大きく、全種に目、アンカーと自動フィット)。差は「線・陰影・光・照り」だけ

| | A 磨き込み | **B トイ・フィギュア** | C セル陰影 |
|---|---|---|---|
| 狙い | 現行の値を保ったまま、形・目・余白だけ直す | 太いふち+内側の照り線+つや玉+強い逆光。ソフビ人形の「手に取れる」感じ | 陰影を 3 段に区切り、硬い逆光の帯と部品ごとの線。グラフィカル |
| 外ふち(192px) | 3.5px | 6px | 4.5px |
| 1 倍の印象 | 整っているが、現行との差が小さい | いちばん「物」らしい。暗い鳥も体の面が読める | 逆光の帯が強く派手。顔に影の斑点ができる |
| 48px | ふちが 0.9px で、暗い体が沈む | ふち 1.5px で外形がいちばんはっきり。目も黄色い点で残る | 逆光の帯は残るが、影の段が斑(まだら)になってにごる |
| 48px 輝度の散らばり(大きいほど立体が読める) | 37〜58 | **47〜66(最大)** | 40〜57 |
| CLAUDE.md の画風との一致 | 一致 | 一致(グラデーション・左上の光・青い逆光・光る目・黒ふち。ふちが太くなるだけ) | ずれる(形ごとのグラデーションをやめるので「立体フィギュア調」から離れる) |
| 既存の 159 種へのあてはめ | 楽(値の変更だけで効く部分が大きい) | 楽(`sprite()` の値と照り線の追加。形の描き直しは別に必要) | 重い(全部品に線と影の帯。細い部品で崩れやすい) |

**推奨: B トイ・フィギュア**

1. 縮小に強い。ゲームで魔生物がいちばん多く出るのは 48px(パーティ・図鑑の一覧・野生の札)。B だけが 48px でも外形・目・体の面の 3 つが読める(`02_compare_48px.png`)。
2. 黒い地の UI と相性がよい。太い黒ふちの内側に、左上の明るい照り線と右下の青い逆光が入るので、濃い色の体でも背景から浮く。弱点 2 と 3 を同時に解決する。
3. CLAUDE.md の「立体フィギュア調」の延長で、方針の変更がいらない。`sprite()` の後処理を変えるだけで 159 種すべてに効き、統一感を一気に上げられる。
4. 「かっこよさ」の主役である目(するどいまぶた)と看板の形が、太いふちで締まって見える。

B の注意点(ルールに反映済み): つや玉は大きな丸い形だけに入れる(小さい部品に入れると白い斑点になる)。暗い体の種は目のまわりに明るい縁(アイリング)を入れる(ハシブトンの目は 48px でまだ弱い)。

不採用の理由: A は安全だが、48px と暗い体の問題が残る。C は 1 倍では派手で魅力があるが、48px でにごり、画風の方針からも外れる。C の「硬い逆光の帯」は、ボスや伝説の特別な演出として部分的に使う余地がある(本バイブルでは採らない)。

## 3. 画風(B トイ・フィギュア)

### 3-1. ひとことで
「黒いふちで縁取った、つやのあるソフビ人形を、左上からの光と右下の青い逆光で撮った写真」。顔はするどく、体は丸く重い。

### 3-2. カメラ
- 向き: **左を向いた斜め横(3/4 ビュー)**で描く。頭は画面の左、しっぽは右。反転が必要な場面はコード側で `scaleX(-1)` する(`.cutin.foe img` と同じ)
- 高さ: 目の高さよりやや上から(見下ろし 10° 程度)。背中の面が少し見え、足は地面に置く
- 遠近は付けない(手前と奥の足の太さは 1 割だけ差をつけてよい)

### 3-3. 線
| 線 | 値(192px キャンバス) | 48 単位の座標では |
|---|---|---|
| 外ふち | **6px**、色 `#070916`、36 方向にずらして塗る | 約 1.67 単位 |
| 内側の照り線 | 外ふちのすぐ内側、左上だけ。形を (2.2, 2.6)px ずらして抜いた幅、`rgba(255,250,235,.75)` | — |
| 部品の中の線(羽の筋・甲の合わせ目) | `g.l` / `g.path`。幅 0.8〜1.2 単位、色はその部品の影色か明るい色 | 0.8〜1.2 |
| 脚・触角などの棒 | 幅 2 単位以上(1.5 未満は 48px で消える) | 2〜3 |

### 3-4. 陰影の段数(5 層)
1. 形ごとのグラデーション(`vol`): 丸い形は放射、多角形は直線。明 `mixc(c,#fff,.34)` → 基本色 → 影 `mixc(c,#141a44,.56)`
2. 全体の高さマップの光: 主光の明るさ 最大 **.48**、影 最大 **.46**(影の色 `rgb(14,18,58)`)、ぼかし半径 8×2 回
3. 右下の逆光: 色 `rgb(96,196,255)`、強さ 最大 **.80**、幅係数 **2.6**
4. つや玉: 大きな丸い形(短径 2.4 単位以上)だけ。中心は形の外接矩形の (32%, 27%)、半径 短辺の 26%、白 α .6
5. 内側の照り線(3-3)

彩度は描画時に +12%(`sat:.12`)。

### 3-5. ライティング
- 主光: **左上**(光の向きのベクトル (-.62, -.78)。左上 約 50°)。白い光
- 逆光: **右下**、青 `#60c4ff`。色違いは金 `#ffd66e`(6 章)
- 影色: 青みの濃紺(`SH='#141a44'`)。黒や灰色で影をつけない
- 地面の影は描かない(UI の `drop-shadow` に任せる)

## 5. シルエットのルール

### 5-1. 体の組み立て
- **頭は大きく**: 頭(顔)の面積は全体の 1/4〜1/3。頭は画面の左上 1/3 に置く(左向き)
- **種の看板をひとつ大きく**: モチーフの特徴(角・葉・くちばし・はさみ・ひれ)を、外形から 1 か所はっきり飛び出させる。看板は外接矩形の 1 辺以上に届く大きさ(例: カブトオーの角は高さの 6 割、ハッパダヌキの葉は頭の幅)
- 胴は「洋なし形」や「ドーム」など重心が低い形。ただの楕円+棒の脚にしない(`blob` を使う)
- 脚は 2 単位以上の太さ。関節で 1 回折る(棒 1 本にしない)

### 5-2. 縮小時の判別
- 48px のシルエット(白い塗りつぶし)だけで、同じ系統の他の種と見分けられること
- 24px でも「頭の向き」と「看板」が分かること
- 形の差は「外形の凹凸」でつける。色や模様だけの差は 48px で消える
- 細い部品(1.5 単位未満)は看板にしない

### 5-3. 覚醒・上位でシルエットが育つ
- 上位形(覚醒・真・合体後)は、通常形の外形を保ったまま **看板を 1.3〜1.6 倍に伸ばし、外形を破る要素を 1〜2 個足す**(`04_growth.png`)
  - 例: ハッパダヌキ → 葉が 2 枚+しっぽの葉。ハシブトン → 翼を上げて広げる・光りものが増える。カブトオー → 角が長く先が開く・背中に棘
- 上位形の占有率は通常形より **+3〜10 ポイント**
- 放射状の光や星だけを重ねる上位形(現行の `shinDraw` 方式)は禁止。光の演出は形の変化に加えて使う
- 描き分けは同じ描画関数に段階 `stg`(0=通常、1=覚醒、2=真)を渡して行う。別の関数に複製しない

## 6. 目のルール

- **全種に目を描く**(`g.eyeC` を 1 回以上。159 種すべて)。目のない生き物(キノコ・植物・クラゲなど)も、「顔」の位置を決めて目を描く
- 大きさ: `sz` は 0.8 以上(B の倍率 1.55 で、虹彩の半径 約 2.1 単位 = 192px で約 7.5px、48px で約 1.9px)。手前の目を 1.0、奥の目は 0.8〜0.9
- まぶた: **前(鼻の側)が低く、後ろが高い**するどい上まぶた。眠そう・悲しそうに見える向き(後ろが低い)は禁止。鳥だけは平らで太い眉
- 反射: 白い点を左上に 1 つ、右下に小さく 1 つ(B の倍率で自動)
- 目の色は系統の `IRIS`(4 章)。色違いは淡い金 `#ffe9a0`
- 暗い体(主色の輝度 60 未満)の種は、目のまわりにアイリング(体の明るい色かアクセント色の楕円、目より 0.6 単位大きい)を入れる

系統別の目の型(`05_eyes_by_family.png`):

| 型 `type` | 系統 | 形 |
|---|---|---|
| `slit` | 獣・竜 | 縦長のスリット瞳孔 |
| `round` | 鳥 | 丸い瞳孔+平らな太い眉 |
| `compound` | 虫 | 瞳孔のないドーム。粒を 4 つ、反射 2 つ、斜めの眉 |
| `leaf` | 植物 | 菱形の瞳孔 |
| `pearl` | 水棲・軟体 | 大きな黒瞳(虹彩は細い輪) |
| `glow` | 霊・？？？？ | 瞳孔のかわりに白い芯(光っている) |
| `lens` | メタル | 横一文字のスリット(レンズ) |

## 7. 色違いの規格

`hue-rotate` はやめる。**パレットの差し替え+光の演出**で、別の絵として描く(`03_compare_shiny.png`)。

1. パレット差し替え: 種ごとに `PAL[id].s` を設計する。色相を回すのではなく、「白化(アルビノ)」「紅葉」「宝石」「月夜」など**意味のある配色**にする
   - 主色は通常形と **色相 60° 以上、または明るさ 30 以上**ちがうこと(48px で一目で分かる差)
   - 目は淡い金 `#ffe9a0`、瞳孔・ふちは変えない
2. 光の演出(3 つとも必須)
   - 逆光を青 → 金 `#ffd66e` に変える
   - 4 方向に尖ったきらめきを 3 つ(外接矩形の右上に大 11px、左上寄りに中 6px、右下寄りに中 7px)。`sprite()` の書き出しに焼き込む
   - UI 側の `✦`(`.seal.sh::after`)は残してよい
3. キャッシュは `id+'_x'` で別に持つ。`seal()` は `shiny` のとき `sprite(id,false,true)` を使い、CSS の `filter` は外す
4. 既存の色を直書きした描画関数の移行期間は、`SHINY[id]={'#a87a48':'#d9d3cc', ...}` の置き換え表で対応する(painter の `col()` が置き換える)

## 9. 描画コードのテンプレート

### 9-1. 描画関数の形
```js
/* 色はパレットのキーで書く。stg は 0=通常 1=覚醒 2=真 */
PAL.kabutoo={n:{shell:'#86401e',shellD:'#5a2412',horn:'#4a1e0e',leg:'#2e1408',hi:'#d08a52',belly:'#3a1a0c'},
             s:{shell:'#2fa07c',shellD:'#16604e',horn:'#c8a03a',leg:'#123a32',hi:'#bff0a8',belly:'#0e3028'}};
DRAW.kabutoo=(g,stg=0)=>{
  // 1) 奥のもの(奥の脚・しっぽ・尾羽) 2) 胴 3) 看板 4) 頭 5) 目、の順に描く
  LEGS(g,[[34,36,41,39],[41,39,45,46],[25,38,23,46]],'leg',2);
  g.blob([[18,26],[30,19],[45,26],[43,38],[24,40]],'shell');
  g.p(stg?[/* 覚醒: 長く開いた角 */]:[/* 通常の角 */],'horn');
  g.e(11,33.5,4,3.4,'belly');
  g.eyeC(11.5,32,.85,'compound');
};
```

### 9-2. painter(`flatPainter`)に足す・変える部品
| 部品 | 仕様 |
|---|---|
| `col(c)` | `c` がパレットのキーならその色、`#rrggbb` ならそのまま(`SHINY` 表があれば置き換え)。全部品で通す |
| `blob(pts,c)` | 点の列を通る閉じた滑らかな形(各辺の中点を結ぶ 2 次曲線)。放射グラデーション+つや玉の対象。胴・頭・葉に使う |
| `eyeC(cx,cy,sz=1,type)` | 中心座標で描く新しい目。`type` を省くと系統の型(6 章)。呼んだ回数を数える(規格チェック用) |
| `eye(a,b)` | 旧来の目(左上座標)。中身は `eyeC(a+1,b+1,1)` に置き換える(既存の 56 種がそのまま新しい目になる) |
| `vol` | つや玉(B)と彩度 +12% を追加。小さい形(短径 2.4 単位未満)は単色のまま |
| `spark(x,y,s,c)` | 4 方向のきらめき。色違い・伝説の演出用 |

## 10. 自動規格チェック

全 159 種(通常・色違い・各段階)を描き出して、次を自動で判定する。見本の実装は `proto.html` の `check()`(`06_check_stats.png`)。

| # | 項目 | 合格の条件 |
|---|---|---|
| 1 | 描画エラー | `DRAW[id]` が例外を出さない(`sprite()` の `catch` で握りつぶさず、テストでは数える) |
| 2 | 不透明率 | α>128 の画素が 30〜60% |
| 3 | 外接矩形 | 長い辺 150px 以上 |
| 4 | 余白 | 上・左・右 12px 以上、下 13px 以上(浮く種は下を除く) |
| 5 | アンカー | 外接矩形の中心 x が 96±3、下端が 178±2(浮く種を除く) |
| 6 | 目 | `eyeC` の呼び出しが 1 回以上。最大の目の `sz` が 0.8 以上 |
| 7 | 48px の縁の明るさ | 48px に縮めて背景 `#14171c` に置き、外形から 2〜3px 内側の画素の平均輝度が **60 以上** |
| 8 | 48px の立体感 | 48px の不透明画素の輝度の標準偏差が **35 以上**(平らすぎない) |
| 9 | シルエットの判別 | 48px シルエット同士の IoU が、同じ系統の他の種と **0.80 以下** |
| 10 | 上位形の成長 | 通常形とのシルエット IoU **0.88 以下**、不透明率 +3 ポイント以上 |
| 11 | 色違いの差 | 主色の色相差 60° 以上、または明るさの差 30 以上。逆光が金になっている |
| 12 | 色数 | パレットのキーが 4〜6 個(目・ふちを除く) |

試作での結果(`06_check_stats.png`): B の 3 体は 2〜8 にすべて合格。現行はハシブトン 27.0%・カブトオー 24.2% で不透明率が不合格、上の余白が 54〜57px。

## 11. 既存 IP に似せないルール

- モチーフは **実在する日本の生き物と民俗**(`S()` の `motif`)から作る。既存作品のキャラクターをモチーフにしない
- 禁止する組み合わせ(ポケモン・デジモン・妖怪ウォッチなどの看板キャラと重なるもの)
  - 黄色い体+赤い丸い頬+稲妻形のしっぽ / 背中に球根や花をのせた四足 / 炎の灯るしっぽのトカゲ / 甲羅を背負った青い子ガメ、の「御三家」構図
  - 丸い大きな黒目だけの顔(このゲームの目は必ずまぶた付きの光る虹彩。6 章)
  - 球形のカプセル・ボール・紅白の 2 色の球
  - 既存キャラの配色をそのまま写すこと(例: 黄+黒縞+赤頬、青+白腹+大耳の組み合わせ)
- 確認の手順: 新しい種は、48px シルエットと配色を「同じ動物モチーフの既存の有名キャラ」と並べて見る。似ていたら看板の形か配色を変える。総監督が採否を判定する
- 名前・図鑑の説明文も、既存作品の決まり文句を使わない
