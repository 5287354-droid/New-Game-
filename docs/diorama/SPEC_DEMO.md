## 0. ひとことで

**机の上の作業台に並んだ「ジオラマの箱庭」を、手のひらサイズの主人公と、ソフビ人形のような魔物(マモノ)が冒険する3D配合育成RPG。**

- 世界は、姿を消した模型師が作ったジオラマです。箱をひとつ攻略するごとに、作業台の上で次の箱がひらきます
- 魔物は、紙・石・ブリキ・布・火・水の「素材」でできた生きた人形です。**配合すると、親のパーツを受けついだ子が組み上がります**
- 画面は本物の3Dです(Three.js)。ミニチュア写真のような**ティルトシフト(上下のぼかし)**で、模型を上からのぞきこんでいる感じを出します

### 前作『ミチクサ鉄道』の反省と、この作品での直し方

| 前作の反省 | この作品での直し方 |
|---|---|
| 1. 魔物の絵が弱かった | 魔物は **Blender で作る3Dモデル**(部位ごとのパーツ)にする。同じ素材・同じライトで描くので画風がそろう。配合で**見た目のパーツが受けつがれる** |
| 2. ギミックに飽きた。見た目だけ違う同じ仕掛けが多かった | **1エリアにつき1つの新しいルール**。同じルールは「新しい能力と組み合わせたとき」だけ再登場させる。町で**フィールド能力(ピンセット)**を手に入れると、前のエリアにも新しい道がひらく |
| 3. 建物の中にマップがない | **すべての建物に入れる**。入ると**屋根と手前の壁が持ち上がって**中が見える。読みこみも画面の切り替えもなし。ジオラマならではの見せ方にする |

## 2. 世界とストーリー(体験版の範囲)

- **舞台:** 古い模型店の奥にある作業台。その上に並んだジオラマの箱が世界です。外側の「巨大なもの」(卓上ランプ、定規、カッターマット、ペン立て)が背景や遠景に見えます
- **主人公:** ネジマキ村に住む見習いの人形。名前はプレイヤーが決めます
- **事件:** 模型師が姿を消してから、ジオラマのつなぎ目がほどけはじめた。村の時計塔が止まり、箱と箱をつなぐ道が消えた
- **体験版のゴール:** 時計塔を動かして、次の箱(「ペン立て山脈」)への道をつなぐ。最後に、次の能力「ノリ」が要る、ちぎれた橋を見せて終わる(予告)

### 体験版の進行(目安の時間)

| # | 場面 | 内容 | 目安 |

## 3. 画面と見た目

### 3-1. 3Dの見せ方(ジオラマ)

- **カメラ:** 狭い画角(25°前後)の透視投影で、斜め上から見下ろします
  - 向きは**90°ずつ4方向**(Q/E、画面の ⟲ ⟳ ボタン、2本指でひねる)。指でドラッグすると ±15° だけ自由に傾き、模型らしい奥行きが出ます
  - 主人公の手前をふさぐ壁や木は**切り抜いて**、断面を見せます(手前を消して中を見る)
- **ティルトシフト:** 画面の上と下をぼかし、ピントは主人公の位置に合わせます(安いシェーダーで、画質「低」では切る)
- **光:** 左上からのやわらかい主光 + 空の色の環境光 + やわらかい影。画質「高」では SSAO(すき間の暗がり)
- **質感:** 地面や建物は「塗装した木・紙・粘土」。角は少し丸め(ベベル)、塗りの小さなムラを入れて、手作りの模型に見せます
- **ジオラマの台:** エリアの外周は木の台の断面で終わり、その外に作業台と巨大な道具が見えます。**世界の端が自然に見えるのが、この作品らしさ**です

### 3-2. 魔物の見た目(ソフビ人形調)

- 共通の質感は、つやのある**ソフトビニール**(少し透ける、ハイライトがやわらかい)と、素材ごとの表面(紙の繊維、石のざらつき、ブリキの打ち出し、布の縫い目、ロウのとろみ、インクのにじみ)です
- **目は光るガラス玉**で、全種で共通の規格にします(大きさ・位置・ハイライトの向き)
- 64px の大きさに縮めてもシルエットで見分けられること。似た形が2種あったら、どちらかを作り直します
- 既存のIP(ポケモン、ドラクエ、デジモンなど)に似せないこと。art-director が毎回確かめます

### 3-3. UI(プラモデルの組立説明書調)

- **地は生成りの紙**(#F4F1EA 前後)、**線は黒いインク**、文字は太いゴシック、数字は Barlow Condensed
- メニューの枠は**ランナー(プラモの枠)**の形。項目にはパーツ番号のような記号(A-1, A-2 …)をつけます
- エリアごとにアクセント色を1色決めます(つみき野 = 黄緑、ランプの森 = 藍、時計塔 = 朱、ネジマキ村 = 山吹)
- 図鑑は「パーツ一覧」、配合は「組み立て手順」(①②③…と番号つきで部品がはまる)という見せ方にします
- 影や光のにじみはUIには使いません。紙と線だけで見せます

| 操作 | スマホ | キーボード |
|---|---|---|
| 移動 | 地面をタップするとそこまで自動で歩く(経路探索)。押し続けると、その方向へ歩く | 矢印キー |

## 5. エリアとギミック(1エリアに1つの新しいルール)

マップは**マス目 + 高さ**のデータで持ちます(5-6 を参照)。広さはどれも大きめにします。

### 5-1. ネジマキ村(町、40×32、アクセント 山吹)

- **ルール: 建物の中**
  - 建物は全部で7つ、すべて入れます: 自宅、工房(配合・預かり所)、よろず屋(買い物)、村長の家、宿屋(回復)、図書小屋(ヒントの本)、時計塔の入口
  - 入口に立つと、**屋根がふわっと持ち上がって横にずれ、手前の壁が透け**、カメラが少し寄ります。出ると元に戻ります。読みこみなし
  - 2階建ての家は、上の階の床がはがれて見えます。階段で上がると、上の階の屋根が持ち上がります
  - 中は家具・本棚・タンスを調べられて、道具が見つかります。住人は時間帯で中と外を行き来します
- 村の中央の広場に、止まった時計塔が見えています(最終目的地を最初から見せる)

### 5-2. つみき野(野外、60×48、アクセント 黄緑)

- **ルール: 回転台(ターンテーブル)**
  - エリアは、丸い**回転台**が5枚組み合わさってできています。台のはしにあるハンドルを回すと、その台が90°回り、上の道・橋・柵の向きが変わります
  - 台どうしの道がつながると先へ進めます。2枚・3枚を順に回すパズルが、奥へ行くほど難しくなります
  - 回転台に乗ったまま回すと、主人公もいっしょに回ります。魔物も台の上にいれば回るので、逃げる魔物をハンドルで追いつめることもできます
- **カメラ回転の練習:** 丘や積み木の裏にだけ見える宝箱・はしごを置きます。3方向からは見えず、1方向からだけ見えます
- **ピンセットの寄り道(あとで来る):** ①折れたはしごの部品を拾って崖にかけると宝箱 ②橋板を運んで池の小島へ渡ると、レア魔物「ハリボテ」の出る巣

### 5-3. ランプの森(野外、56×48、アクセント 藍)

- **ルール: 光と影**
  - 森の外、作業台の上に**巨大な卓上ランプ**があり、森全体を照らしています。森の中に3か所の「ランプ台」があり、乗って調べるとランプの角度が変わります(東・真上・西の3段階)
  - 切り絵の木や岩の**影が、谷の上に「影の橋」として落ちます**。影の上だけは歩けて、光の当たる谷は落ちてしまいます(落ちたら直前の足場にもどるだけで、痛みはなし)
  - 角度ごとに影の形が変わるので、「東で半分渡り、ランプ台で真上に変えて残りを渡る」のような順番のパズルになります
  - 影の中にだけ出る魔物と、光の中にだけ出る魔物がいます
- **ぬし: カゲボウシ**(布 + 影の魔物)。戦闘中もランプの角度が「光 / 影」で切り替わり、影のターンは物理わざがほとんど当たりません。光のターンを読んで攻めます

### 5-4. ゼンマイ時計塔(ダンジョン、1階 24×24 × 6階、アクセント 朱)

- **ルール: 時計の針で塔を回す + ピンセット**
  - 各階の中央に文字盤があり、針を 12時・3時・6時・9時 に合わせると、**その階の外周の床がまるごと回ります**。回った床の通路の向きで、上り階段への道が変わります
  - 歯車の付いていない軸に、ピンセットで歯車を付けかえると、上下の階の回転がつながります(1つの階を回すと別の階も回る)。歯車の大小で回る量が変わります(大きい歯車=半分だけ回る)
  - 振り子の通路: 一定のリズムで振り子が通路をふさぎます。リズムは BGM の拍と合わせます
  - 塔は**断面で見せます**。カメラを回すと塔の切り口が変わり、上下の階のつながりが見えます
- **ボス: トケイモリ**(ブリキの大ヤモリ。背中に文字盤)。戦闘中、針が進むたびに戦場の回転台が回り、前列と後列が入れかわります
- 6階のうち、5階は「ピンセットを使わないと開かない」宝の部屋を1つ持ちます

### 5-5. 作業台(エリアを選ぶ画面)

- 作業台の全体を見下ろし、ジオラマの箱をタップしてそのエリアへ行きます。まだ開いていない箱は、布がかかっています
- 次の箱「ペン立て山脈」は、ちぎれた橋(「ノリ」が要る)の先に見えるだけです

### 5-6. マップのデータとソルバー

- 1エリア = マス目(幅 × 奥行き)ごとの `{高さ, 地面の種類, 上に乗る物}` + ギミックの状態。データは JSON で、**エディタで手直しできる形**にします
- ギミックの状態(回転台の向き、ランプの角度、各階の針、歯車の位置、ピンセットで運んだ物)を合わせて1つの「状態」とみなし、**状態ごとに幅優先探索をするソルバー**を `tools/solver/` に置きます
  - 確かめること: 入口から全部の宝箱・出口・ぬしに届くこと / どの状態からでも入口に戻れること(詰まない) / 必要な能力なしでは届かない場所が、意図したとおりになっていること
  - ピンセットで運んだ物は、エリアを出ると元の場所に戻ります(戻す仕組みがあれば、詰みにはなりません)。ただし「正しく置いたもの」は覚えておきます
- ソルバーは CI と同じように、テストとしていつでも流せるようにします

## 6. 魔物

### 6-1. 素材の属性(6つの輪)

**水 → 火 → 紙 → 石 → ブリキ → 布 → 水**(矢印の先に強い。1.5倍 / 逆は0.67倍)

- 水は火を消す・火は紙を燃やす・紙は石を包む・石はブリキをへこませる・ブリキ(はさみ)は布を切る・布は水を吸う、という覚えやすい理由をつけます

### 6-2. 体の型(6種)とパーツ

体の型は **まる・しずく・四つ足・鳥・へび・人形** の6種類です。どの魔物も「胴(型) + 頭 + 背中 + しっぽ(または手持ち)」の4か所のパーツでできています。パーツどうしは、Blender で付けた**つなぎ目(ソケット)**でつながります。

### 6-4. 成長

- レベルの上限は体験版では 30。能力値は HP・MP・こうげき・まもり・すばやさ・かしこさ の6つ
- わざは1体に最大4つ。レベルで覚えるわざ(種ごとに4〜6個) + 配合で受けつぐわざ
- わざは 30〜40種(属性わざ・補助・回復・パーツ由来のわざ)。数字の調整は balancer が測って決めます

## 7. 戦闘

- **場所:** 戦闘になると、そのエリアの小さな**丸い対戦台**(ジオラマの一部を切り取った台)の上に魔物が並びます。フィールドからカメラが寄って、台がせり上がる演出でつなぎます(暗転しない)
- **形式:** 3対3のターン制。全員のコマンドを選ぶ → すばやさ順に動く。前列2体・後列1体で、後列は受けるダメージが減り、近接わざが届きません。「いれかえ」で前と後ろを替えられます
- **コマンド:** たたかう / わざ / いれかえ / どうぐ / スカウト / にげる
- **スカウト:** 相手の HP が少ないほど、こちらの同じ素材の魔物が多いほど成功しやすくなります。道具「つやだしニス」で確率が上がります。成功すると、人形がくるっと回って箱に収まる演出
- **手ざわり:** 当たったら一瞬止める(ヒットストップ)、人形が跳ねる、弱点はパーツが少しはずれかけて戻る、倒れるとパタンと横倒し(ソフビらしく)。ダメージの数字は説明書の部品番号のような書体で出す
- **出会い方:** シンボルエンカウント。フィールドを魔物の人形が歩き回っていて、触れると戦闘になります。後ろから触れると先制。レアは光る台座の上で眠っています
- **負けたとき:** 所持金が半分になり、最後の宿屋で目覚めます

## 8. 配合(この作品のいちばんの売り)

- **場所:** ネジマキ村の工房。Lv10 以上の2体から、1体を生み出します(親2体はいなくなります)
- **子の種族:** 「素材 × 素材」「型 × 型」の表と、特別な組み合わせの表で決めます。表は `data/breed.json` に置き、**全部の組み合わせが埋まっている**ことをテストで確かめます
- **見た目の受けつぎ(おさがりパーツ):** 子は、親のどちらかから**パーツを1か所だけ受けつぎます**(頭・背中・しっぽのどれか。プレイヤーが選べる)
  - 受けついだパーツは、子の素材の色と質感で塗り直されます(画風がくずれない)
  - パーツには小さな効果がつきます(例: ネジコの「ねじ巻き」を背負うと、すばやさ+5%)
  - おさがりは代々重ねられます(孫は親からおさがり付きのパーツを受けつげる)。**同じ種でも、見た目が1体ずつ違う**のが目標です
- **わざの受けつぎ:** 親のわざから2つまで選んで受けつぎます
- **能力の受けつぎ:** 子は Lv1 から。親のレベルの合計に応じて、能力値の伸びにボーナスがつきます
- **演出:** 組立説明書の見開きになって、①ランナーから部品を切りはなす ②組み合わせる ③パチッとはまる、を番号つきで見せます。最後に、完成した子が台の上でくるりと回ります

## 9. フィールド能力: ピンセット

- ランプの森のぬしを倒したあと、工房でもらいます
- フィールドで、**ランナーのタグ(四角い小さな札)がついた物**だけをつまめます: はしごの部品、橋板、歯車、積み木
- つまんだ物は、それに合う**くぼみ(ソケット)**にだけ置けます。合う場所は、近づくと点線で光ります
- 一度に持てるのは1つ。持ったままエリアを移ることはできません
- 使い道: 時計塔(歯車の付けかえ)、つみき野の寄り道2か所、時計塔5階の宝の部屋
- **次の能力の予告:** 「ノリ」(ちぎれた物をくっつける)。体験版の最後の、ちぎれた橋で見せます

## 10. 音

- WebAudio でコードの中で鳴らします(外部の音声ファイルは使わない)
- テーマは**オルゴール**。村の曲を、エリアごとに楽器と編成を変えて展開します(つみき野 = 木琴と口笛、森 = 低いオルゴールと鈴、時計塔 = チクタクの打楽器と金管)

- 音量は BGM と効果音を別々に5段階

## 11. 技術

### 11-1. 構成

- **静的な Web アプリ(PWA)**。ビルドなしで動く ES モジュール構成にします
  - `index.html` / `src/*.js` / `data/*.json` / `assets/models/*.glb` / `vendor/three/`(Three.js は **r160 に固定して同梱**。CDN に頼らない。オフラインで動くように Service Worker でキャッシュ)
- 3Dモデルは glTF(.glb)。Draco などの圧縮は、読みこみ合計が 15MB を超えそうなら入れる
- マップは JSON から、**InstancedMesh** でまとめて描きます(同じブロックは1回の描画)
- 画質は 低・中・高 の3段階。最初の数秒の fps を見て自動で選び、設定で変えられるようにします
  - 低: 影は1枚・ぼかしなし・ピクセル比1 / 中: やわらかい影・ティルトシフト / 高: SSAO・ピクセル比2

### 11-2. 魔物と小物を作る流れ(Blender)

1. **Phase 0 で必ず確かめること:** このクラウド環境で `pip install bpy`(Python から使う Blender)が動き、スクリプトで .glb を書き出せるか
2. 動いたら、パーツを **Python スクリプトで作ります**(`tools/blender/`)。形の作り方はプリミティブ + 細分割 + ベベル + 変形(ゆがみ・ふくらみ)。スクリプトなので、何度でも作り直せて、全種で同じ規格になります
3. 各パーツにはソケット(`socket_head` などの名前の空オブジェクト)と、マテリアルのスロット(本体・差し色・目)を入れます。色は実行時に素材ごとに塗ります
4. 確認用に、Blender で回転のコマ画像(8方向)も書き出し、art-director が一覧で判定します
5. **bpy が動かなかったときの代わり:** 同じパーツの規格のまま、Three.js のコードで形を作ります(`src/forge/`)。この場合も、あとで Blender の版に差しかえられるようにします
6. 生成AIの画像は使いません(150体まで増やしたときに画風がそろわないため)

### 11-3. セーブ

- localStorage に版番号つきの JSON で保存。版を上げるときは移行の関数とテストを必ず書きます
- 保存するもの: 主人公の位置・エリア・時刻 / 仲間と預かり(おさがりパーツの履歴を含む) / 図鑑 / 各エリアのギミックの「解いた」状態 / 宝箱 / 道具とお金 / 能力
- 「書き出し / 読みこみ」(テキストでのバックアップ)をつけます

### 11-4. テスト

- `tests/` に node のテスト(データの整合性、配合表の網羅、ダメージ計算、セーブ移行)
- `tools/solver/` のソルバー(全エリア)
- Playwright の通しプレイ(デバッグ用の操作口 `window.__debug` を使って、新しく始めてからエンディングまで)。ヘッドレスでは GPU が弱いので、fps ではなく `renderer.info` の数字で性能を見ます
- スクショ: スマホ縦・横で、各エリア・戦闘・配合・図鑑を撮って `docs/shots/` に置きます

## 12. 開発の進め方(いつもの軍隊方式)

部隊の定義は [kit/.claude/agents/](kit/.claude/agents/) にあります。総司令官(メインのセッション)は自分で量産せず、各班に仕事を割りふり、統合と判断をします。

### 12-1. 部隊

| 班 | 担当 |
|---|---|
| 総司令官(メイン) | 計画、割りふり、統合(マージ)、判断、オーナーへの報告 |
| scout 偵察隊 | 技術の下調べ(bpy、Three.js の性能、スマホでの動き) |
| game-designer 企画参謀 | DESIGN.md(この仕様書をくわしく)、わざ表、配合表、エリアの設計図 |
| art-director アート総監督 | ART_BIBLE.md、全ビジュアルの合否。自分では作らない |
| monster-forge モンスター工房 | Blender のパーツスクリプト、20種の組み立て、色違い |
| diorama-builder ジオラマ大工 | マップのデータ、ギミックの実装、ソルバー |
| tech-artist 技術美術班 | 描画(光・影・ティルトシフト・切り抜き・屋根が開く演出)、性能 |
| engineer 実装班 | 戦闘、配合、セーブ、UI の仕組み、テスト |
| ui-fx UI/演出班 | 説明書調の UI、戦闘と配合の演出、手ざわり |
| sound-lab 音響班 | オルゴールの曲、効果音 |
| balancer バランス解析班 | 成長曲線、ダメージ、出現率、スカウト率をシミュレーションで調整 |
| qa QA小隊 | 自動テスト、通しプレイ、スクショ、不具合の報告 |
| auditor 監査官 | 作っていない立場から辛口の採点(8.5/10 で合格) |

### 12-2. 作戦の段階

| 段階 | やること | 出すもの |
|---|---|---|
| **Phase 0 技術検証** | bpy でパーツ1つを作って .glb に書き出す → Three.js で表示。マップ 60×48 を InstancedMesh で描いて `renderer.info` を測る。ティルトシフトと屋根が開く演出を試作 | `docs/RECON.md`、試作のスクショ。**ここで Blender か代わりの方法かを決める** |
| **Phase 1 作戦立案** | DESIGN.md、ART_BIBLE.md(魔物の試作3体で画風を決める。A案・B案を比べる)、エリアの設計図(紙のマス目の図)、わざ表・配合表 | `docs/DESIGN.md` `docs/ART_BIBLE.md` `docs/maps/*.md` `data/*.json` |
| **Phase 2 量産** | 班ごとに worktree(別の作業場所)で並行して作る。エリアは1つ作るごとにソルバーを通す | 各班のブランチ |
| **Phase 3 統合** | 全ブランチをマージ。テストを全部通す | 統合したブランチ |
| **Phase 4 検証** | QA の通しプレイ、監査を3回まで(指摘を直して出し直す)。8.5/10 以上で通過 | `docs/QA.md` `docs/AUDIT.md` |
| **Phase 5 納品** | REPORT.md(何を作ったか、スクショ、残った課題)、遊び方を README に | `docs/REPORT.md` |

### 12-3. 守ること

- `docs/PROGRESS.md` に進み具合のチェックリストを置き、段階ごとに更新する
- 決めたことは `docs/DECISIONS.md`、困ったことは `docs/ISSUES.md`、有料の API を使ったら `docs/COST.md`(基本は使わない)
- main に push しない。デプロイしない(オーナーが判断する)
- 各班の報告は 200字以内の要約 + 成果物のパス
- 確認の質問で止まらない。決めて作り、何を決めたかを短く報告する

## 13. 体験版のあとに(製品版の見通し。今回は作らない)

- 箱(エリア)を8つ: ペン立て山脈(ノリ)、カッターマットの海(定規の橋)、絵の具パレットの火山(混色)、本棚の迷宮(ページをめくる)…。**箱ごとに能力1つ・新しいルール1つ**
